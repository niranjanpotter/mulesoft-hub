# .github/workflows/mule-ci-cd.yml
name: Mule 4.9 CI-CD Pipeline
on:
  push:
    branches: [ main ]
jobs:
  build-test-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { java-version: '17', distribution: 'temurin', cache: 'maven' }
      - name: Run MUnit Coverage Gate (80%+)
        run: mvn -B clean test -s .maven/settings.xml
      - name: Deploy to CloudHub 2.0 Sandbox
        run: |
          mvn -B mule:deploy -DskipTests -s .maven/settings.xml \
            -Danypoint.ca.id=${{ secrets.CA_CLIENT_ID }} \
            -Danypoint.ca.secret=${{ secrets.CA_CLIENT_SECRET }} \
            -Dmule.env=Sandbox -Dmule.key=${{ secrets.SANDBOX_KEY }}

Architecture Deep-Dive Q&A

Q1 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

How do you enforce 80% MUnit code coverage gates in a Maven build?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

Configure the munit-maven-plugin configuration block inside pom.xml with coverage limits: set applicationCoverage, resourceCoverage, and flowCoverage to 80. If code coverage falls below 80%, the build fails automatically, preventing deployment.

💻 CODE / ARCHITECTURE CONFIGURATION
<coverage>
  <runCoverage>true</runCoverage>
  <failBuild>true</failBuild>
  <requiredApplicationCoverage>80</requiredApplicationCoverage>
</coverage>
Q2 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

How do you inject encrypted secure property keys safely into CloudHub 2.0 in GitHub Actions?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

Store the master encryption key in GitHub Repository Secrets (MULE_KEY). In the CI/CD workflow, pass the key as a dynamic parameter: -Danypoint.platform.client_id=$CLIENT_ID -Dsecure.key=$MULE_KEY, ensuring keys never touch source code.
