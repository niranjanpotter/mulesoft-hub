<mule xmlns="http://www.mulesoft.org/schema/mule/core"
      xmlns:salesforce="http://www.mulesoft.org/schema/mule/salesforce">

    <salesforce:create-job-bulk-api-v2 config-ref="Salesforce_JWT_Config"

    <set-variable variableName="sfJobId" value="#[payload.id]"/>

        <salesforce:retrieve-job-failed-results-bulk-v2 config-ref="Salesforce_JWT_Config" id="#[vars.sfJobId]"/>
        <logger level="WARN" message="#['Saved failed Bulk 2.0 rows for job ' ++ vars.sfJobId]"/>
      </when>
    </choice>
  </flow>
</mule>

Architecture Deep-Dive Q&A

Q1 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

When should you choose Salesforce Bulk API 2.0 over standard REST/SOAP APIs?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

Standard REST API is optimized for real-time synchronous transactions (<2,000 records). Bulk API 2.0 is designed for asynchronous batch ingest of datasets exceeding 10,000 records up to 100 million records. Bulk API 2.0 automatically chunks uploads, monitors server processing, and minimizes API call count against 24-hour governor limits.

Q2 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

How do you handle QueryLocator cursor timeouts during large SOQL queries?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

Salesforce QueryLocator cursors expire after 15 minutes of inactivity. When processing large query deltas, we stream results in batches or transition to Bulk Query, which stages the result set as CSV files in Salesforce storage, allowing non-blocking downloads.
