Salesforce Connect (OData, GraphQL, SQL) vs. MuleSoft for External Systems

When should you virtualize external data with Salesforce Connect External Objects vs. orchestrate it through MuleSoft APIs or Data Cloud Zero Copy?

⚡ Quick Answer

Salesforce Connect virtualizes external records on-demand inside Salesforce (zero storage cost, real-time UI/SOQL reads via OData 2.0/4.0, GraphQL, or SQL adapters). MuleSoft is best when you need to expose legacy systems as OData/GraphQL APIs, run asynchronous event-driven syncs, or orchestrate multi-system writes.

Combined PatternExpose SAP/Oracle via a MuleSoft OData/GraphQL System API, then bind it to Salesforce Connect for live UI reads.

Production Watchouts with External Objects

  • Server-Side Pagination & `$top`/`$skip`: Always implement OData server-driven pagination in your MuleSoft System API so large external tables don't time out Salesforce's 120-second callout window.
  • Governor & Callout Limits: External Objects still count toward Salesforce synchronous callout timeouts and daily OData callout allocations depending on your license tier.
  • Reporting & Triggers: Standard Salesforce triggers and native roll-up summaries do not fire on External Objects—use MuleSoft Change Data Capture (CDC) or Platform Events when downstream automation is required.
