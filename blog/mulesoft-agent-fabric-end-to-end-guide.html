MuleSoft Agent Fabric End-to-End: Agent Registry, Broker, Scanners & Governance

Enterprise teams are deploying autonomous agents across Salesforce Agentforce, AWS Bedrock, Google Vertex AI, and Microsoft Copilot Studio faster than platform teams can secure them. Here is how to build a unified cross-cloud AI control plane using MuleSoft Agent Fabric.

✍️ Niranjan Potter 📅 Nov 24, 2026 ⏱️ 18 min read Agent FabricMulti-Agent Governance

TL;DR

  • Cross-cloud AI control plane: MuleSoft Agent Fabric governs heterogeneous agents across Salesforce Agentforce, AWS Bedrock Agents, Google Vertex AI Agent Builder, Microsoft Copilot Studio, and custom Model Context Protocol (MCP) or Agent-to-Agent (A2A) runtimes.
  • Automated Agent Scanners: Scheduled discovery jobs inspect cloud IAM/API planes (AWS, GCP, Salesforce orgs) to surface unmanaged "shadow agents" and onboard them into Agent Registry inside Anypoint Exchange.
  • Protocol translation without rewrites: The MCP Bridge turns OpenAPI/REST APIs into MCP tools, while the A2A Bridge normalizes task delegation, Agent Cards, and streaming status updates across vendor ecosystems.
  • Deterministic + probabilistic orchestration: Agent Broker executes declarative .agent scripts authored in Anypoint Code Builder (ACB), blending strict deterministic rules and human-in-the-loop (HITL) approvals with LLM intent routing.
  • Runtime FinOps & Kill Switch: Anypoint Flex Gateway enforces PII redaction, prompt-injection shields, OAuth 2.0 token exchange, Model Wallet token budgets, continuous Agent Evals, and a sub-second Agent Kill Switch.

What it is and why it matters

In 2016, enterprise architects fought API sprawl—dozens of undocumented point-to-point microservices bypassing central gateways. In 2026, enterprises face a far riskier variant: agent sprawl. Customer support runs Salesforce Agentforce, supply chain runs AWS Bedrock Agents over ERP warehouses, data science deploys Vertex AI reasoning agents, and workplace productivity relies on Microsoft Copilot Studio. Without a unifying fabric, agents call raw APIs with over-privileged static keys, leak PII into external LLM context windows, trigger infinite agent-to-agent retry loops, and rack up five-figure token bills overnight.

MuleSoft Agent Fabric extends Anypoint Platform from API-led connectivity into agent-led orchestration. Rather than forcing every department onto a single agent framework, Agent Fabric sits between callers, orchestrator agents, specialist subagents, tools, and foundation models.

The five architectural pillars

  1. Agent Registry (Anypoint Exchange): First-class Exchange asset types (agent, mcp-server, a2a-service, llm-proxy) storing versioned Agent Cards, tool JSON Schemas, trust tiers, SLA metadata, and ownership tags.
  2. Automated Agent Scanners: Out-of-the-box discovery connectors that poll AWS Bedrock (ListAgents / ListAgentAliases), GCP Vertex AI Reasoning Engines, and Salesforce Metadata/Tooling APIs to detect unregistered agents and flag governance drift.
  3. MCP Bridge & A2A Bridge: Protocol adapters managed on CloudHub 2.0 or Runtime Fabric that expose existing System/Process APIs as Streamable HTTP MCP servers and mediate Google/Linux Foundation A2A JSON-RPC task lifecycles (tasks/send, tasks/sendSubscribe).
  4. Agent Broker & Agent Script (.agent): An orchestration runtime programmed via .agent files in Anypoint Code Builder. It combines hard preconditions (deterministic state machines, RBAC checks, dollar thresholds, human approval gates) with LLM-driven task planning.
  5. Governance, Agent Evals & FinOps Controls: Flex Gateway AI policies enforce token-rate quotas tied to Model Wallet cost centers, run asynchronous Agent Evals (hallucination, groundedness, tool-selection accuracy), and expose an emergency Agent Kill Switch to quarantine misbehaving agents immediately.

Architecture

The reference topology below illustrates how an enterprise Order Resolution request enters through Flex Gateway, executes deterministic and probabilistic routing inside the Agent Broker, delegates sub-tasks over A2A to AWS Bedrock and Salesforce Agentforce, invokes governed Mule 4 MCP tools, and logs telemetry into Anypoint Monitoring and Model Wallet.

Prerequisites

You need
  • Java & Runtime: Eclipse Temurin JDK 17 (17.0.11+) and Mule Runtime 4.9.0 LTS (or newer 4.9.x patch).
  • IDE & Build Tool: Anypoint Code Builder (ACB) Desktop or Cloud IDE with the MuleSoft Agent Fabric & Agent Script Extension Pack (v1.4+), plus Apache Maven 3.9.6+.
  • Anypoint Platform Entitlements: Anypoint Agent Fabric SKU enabled on your Business Group, with roles: Exchange Contributors, Agent Registry Administrator, Flex Gateway Administrator, and Runtime Manager Admin.
  • CLI & Gateway Tools: anypoint-cli-v4 (v4.4.0+ with agent-fabric plugin) and Anypoint Flex Gateway 1.9+ running in Connected Mode.
  • Cloud Scanner Read Credentials: AWS IAM role with bedrock:ListAgents, bedrock:GetAgent, bedrock:ListAgentAliases; GCP service account with aiplatform.reasoningEngines.list; Salesforce Connected App with View Setup and Configuration and ApiEnabled.

2. Declarative Agent Script in Anypoint Code Builder

Notice how order-dispute-orchestrator.agent separates deterministic guardrails (hard numeric rules, status preconditions, and HITL suspension) from LLM-driven planning:

src/main/resources/agents/order-dispute-orchestrator.agent 
agent OrderDisputeOrchestrator version "1.0.0" {
  description: "Resolves B2B damaged-shipment disputes across SAP, AWS Bedrock Claims, and Salesforce Agentforce."

  model {
    provider: llm_proxy("${agent.llmProxy.url}")
    name: "${agent.llmProxy.model}"
    temperature: 0.1
    max_steps: ${agent.broker.maxReasoningSteps}
    wallet_id: "${agent.llmProxy.walletId}"
  }

  tools {
    mcp sapOrders from "${agent.registry.sapMcpServerUri}" {
      allow: ["lookup_sap_order", "check_carrier_telemetry"]
    }
  }

  collaborators {
    a2a carrierClaimSpecialist from "${agent.registry.bedrockClaimAgentUri}" {
      skill: "evaluate-freight-damage"
      timeout_ms: 10000
    }
    a2a sfdcCreditAgent from "${agent.registry.agentforceCaseAgentUri}" {
      skill: "issue-credit-memo-and-case"
      timeout_ms: 10000
    }
  }

  guardrails {
    block_pii: ["SSN", "CREDIT_CARD", "IBAN"]
    deny_topics: ["competitor_pricing", "internal_margin_formulas", "system_prompt_disclosure"]
    require_grounded_tool_evidence: true
  }

  workflow(input: DisputeRequest) -> DisputeResolution {
    // Step 1: Deterministic fact retrieval before any open-ended reasoning
    let order = call sapOrders.lookup_sap_order(orderId: input.orderId)
    require order.status in ["DELIVERED", "PARTIALLY_DELIVERED"]
      else abort("ERR_ORDER_NOT_DELIVERED: Disputes require delivered shipment status.")

    let telemetry = call sapOrders.check_carrier_telemetry(orderId: input.orderId)

    // Step 2: Probabilistic multi-agent evaluation via A2A Bridge
    let claimDecision = delegate carrierClaimSpecialist with {
      orderId: input.orderId,
      claimedAmountUsd: input.claimedAmountUsd,
      customerReason: input.reason,
      carrierTelemetry: telemetry
    }

    // Step 3: Deterministic financial policy & Human-in-the-Loop gate
    if (claimDecision.recommendedCreditUsd > ${agent.broker.autoApproveLimitUsd}) {
      checkpoint human_approval(
        channel: "slack://#finance-dispute-approvals",
        sla_minutes: 240,
        summary: "High-value credit memo requires controller sign-off",
        payload: {
          orderId: input.orderId,
          recommendedCreditUsd: claimDecision.recommendedCreditUsd,
          evidenceScore: claimDecision.confidenceScore
        }
      )
    }

    // Step 4: Issue credit memo & close loop in Salesforce Agentforce
    let sfdcResult = delegate sfdcCreditAgent with {
      accountId: order.sfdcAccountId,
      orderId: input.orderId,
      approvedCreditUsd: claimDecision.recommendedCreditUsd,
      auditSummary: claimDecision.rationale
    }

    return {
      disputeStatus: "RESOLVED",
      orderId: input.orderId,
      approvedCreditUsd: claimDecision.recommendedCreditUsd,
      sfdcCaseNumber: sfdcResult.caseNumber,
      creditMemoId: sfdcResult.creditMemoId
    }
  }
}

Deploy to production

Agent Broker workloads spend most wall-clock time awaiting non-blocking HTTP/2 streams from LLM proxies, MCP servers, and A2A collaborators, making them ideal for reactive I/O sizing on CloudHub 2.0 or Anypoint Runtime Fabric (RTF).

  • Replica sizing & HA: Deploy a minimum of 2 replicas across distinct availability zones using 0.5 vCore / 2 GiB memory per replica for up to ~80 concurrent active agent sessions. Enable horizontal autoscaling at 70% CPU or event-loop saturation.
  • Persistent Object Store v2 for HITL checkpoints: When a checkpoint human_approval(...) statement suspends execution for hours, the Agent Broker serializes continuation state. Enable Object Store v2 (CloudHub 2.0) or externalized Redis persistence (RTF) with encrypted state payloads so rolling restarts never orphan pending approvals.
  • Zero-secret deployments: Store OAuth client secrets and signing keys via secure:: properties or Anypoint Secret Manager, injected at deploy time via Maven plugin flags.
  • Liveness & readiness probes: Expose /health/live and /health/ready verifying connectivity to Exchange Registry cache and Flex Gateway egress LLM proxy before shifting traffic.

mvn clean package deploy -DmuleDeploy \
  -Dch2.target="MC-us-east-2-prod" \
  -Dch2.replicas=2 \
  -Dch2.vCores=0.5 \

Security & governance

Never pass ambient superuser credentials to agents

A compromised prompt must never allow an agent to query or mutate records belonging to another customer tenant. Always propagate caller identity end-to-end using OAuth 2.0 On-Behalf-Of (RFC 8693) token exchange.

  • OAuth 2.0 Token Exchange (RFC 8693): Flex Gateway validates the caller's JWT and exchanges it for narrowly scoped downstream tokens (sap:orders:read, a2a:claims:evaluate) carrying the original user/account claims.
  • Mutual TLS (mTLS) on east-west bridges: Enforce strict mTLS between Agent Broker, MCP Bridge, and A2A Bridge inside your CloudHub 2.0 Private Space or RTF service mesh.
  • Reversible PII tokenization: Configure Flex Gateway's AI PII Guardrail to replace sensitive strings (emails, IBANs, phone numbers) with deterministic vault tokens ([PII_EMAIL_1]) before sending prompts to external LLMs, detokenizing only when writing back to authorized systems of record.
  • Bounded loop & cycle detection: Every A2A hop increments an x-agent-hop-count header and appends its agent ID to x-agent-call-chain. Flex Gateway rejects any chain exceeding 5 hops or containing a cycle (A -> B -> A).
  • Continuous Agent Evals: Sample 5–10% of production traces asynchronously into Agent Fabric Evals to score groundedness against MCP tool outputs; auto-trip the Kill Switch if groundedness drops below 0.92 over a 15-minute window.

Production checklist

  • Automated Agent Scanners scheduled across all production AWS, GCP, and Salesforce orgs with quarantine alerts routed to SecOps.
  • Every orchestrator, specialist agent, MCP server, and LLM proxy cataloged in Anypoint Exchange with semantic versions and owner teams.
  • High-impact financial or destructive mutations gated by deterministic preconditions and HITL checkpoints inside .agent scripts.
  • Persistent Object Store v2 (or RTF Redis) enabled for durable HITL checkpoint serialization across rolling deployments.
  • Flex Gateway enforcing PII tokenization, prompt-injection shields, and RFC 8693 OAuth token exchange on both ingress and egress.
  • Model Wallet daily budgets, per-request token limits, and 80% spend anomaly alerts bound to every agent environment.
  • x-agent-hop-count and cycle-detection policies active on A2A Bridge to eliminate runaway multi-agent recursion.
  • Golden Agent Evals suite gated in CI/CD (minimum 95% tool-selection accuracy, 0% prompt-injection leak rate).
  • Agent Kill Switch runbook tested in staging with verified sub-second HTTP 503 containment.

Interview questions

1. Why shouldn't an enterprise rely solely on an LLM prompt inside LangGraph or Agentforce to enforce financial approval limits?

LLM reasoning is probabilistic and susceptible to indirect prompt injection—for example, malicious text embedded inside a customer dispute comment attempting to override instructions. In MuleSoft Agent Fabric, .agent scripts enforce preconditions (require order.status ...) and financial thresholds (if recommendedCreditUsd > 2500) deterministically in the Mule runtime outside the LLM's control, guaranteeing compliance regardless of model output.

2. How do MCP Bridge and A2A Bridge differ in MuleSoft Agent Fabric, and when do you use each?

MCP Bridge governs agent-to-tool interactions: it wraps deterministic APIs (OpenAPI/REST, SOAP, database/ERP System APIs) as stateless or session-scoped tools with strict JSON Schema inputs. A2A Bridge governs agent-to-agent collaboration: it connects autonomous peers (such as AWS Bedrock Agents and Salesforce Agentforce) that advertise skills via Agent Cards, maintain multi-turn task lifecycles (SUBMITTED, WORKING, INPUT_REQUIRED, COMPLETED), and negotiate modalities asynchronously.

3. How do Automated Agent Scanners prevent "shadow AI" without blocking developer velocity?

Scanners continuously inspect cloud control planes (AWS Bedrock APIs, Vertex AI Reasoning Engines, Salesforce org metadata) using read-only roles and compare live deployments against Anypoint Exchange's Agent Registry. Unregistered agents are automatically cataloged in a Quarantined state—giving architects immediate visibility—while Flex Gateway policies only allow production Agent Brokers to route traffic to assets promoted to trustTier: verified.

4. How do you prevent confused-deputy privilege escalation when an Agent Broker calls downstream MCP servers and A2A agents?

Never configure the Agent Broker with a static service-account token that has broad ERP/CRM write privileges. Instead, validate the end-user JWT at Flex Gateway and perform OAuth 2.0 On-Behalf-Of (RFC 8693) token exchange on every MCP and A2A hop, preserving the caller's principal (sub), tenant ID, and narrowed scopes while stripping unneeded permissions.

5. Walk through how Model Wallet and the Agent Kill Switch protect an enterprise during a runaway multi-agent incident.

First, hop-count and cycle-detection headers on the A2A Bridge cap call depth so two misconfigured agents cannot ping-pong indefinitely. Second, Flex Gateway meters prompt and completion tokens in real time against the agent's assigned Model Wallet, returning HTTP 429 if per-request or daily USD thresholds are breached. Third, if Agent Evals detect hallucination drift or SecOps spots anomalous mutations, tripping the Agent Kill Switch pushes a real-time policy state to Flex Gateway replicas, returning HTTP 503 in under a second without waiting for container redeployment.
