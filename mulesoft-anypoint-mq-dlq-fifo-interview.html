    <os:store key="#['mq:' ++ payload.eventId]" objectStore="MQ_Dedup_OSv2"><os:value><![CDATA[PROCESSED]]></os:value></os:store>
    <flow-ref name="process-order-subflow"/>
    <anypoint-mq:ack config-ref="Anypoint_MQ_Config" ackToken="#[vars.mqAckToken]"/>
    <error-handler>
      <on-error-propagate type="ANY">
        <anypoint-mq:nack config-ref="Anypoint_MQ_Config" ackToken="#[vars.mqAckToken]"/>
      </on-error-propagate>
    </error-handler>
  </flow>
</mule>

Architecture Deep-Dive Q&A

Q1 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

Why is MANUAL Acknowledgement mode preferred in mission-critical billing flows?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

With AUTO or IMMEDIATE ACK, if a MuleSoft worker crashes mid-flow after receiving a message, the message is permanently lost. With MANUAL ACK, the message remains locked until the entire database or ERP commit succeeds. If an unrecoverable exception occurs, a NACK or timeout releases the message back to the queue for retry.

Q2 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

How do you configure a Dead Letter Queue (DLQ) to isolate poison pill messages?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

In Anypoint MQ Manager, we assign a DLQ to the primary queue with a maxDeliveryAttempts threshold (e.g., 5). If a malformed payload causes recurring exceptions across 5 attempts, Anypoint MQ automatically diverts the message to the DLQ, alerting support teams without stopping queue processing.
